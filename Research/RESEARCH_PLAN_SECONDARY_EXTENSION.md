## 1. Purpose

Record the proposed next-stage pattern identified for work **after the complete Earth research track has been carried through its agreed layers and its Master Report(s) have been assembled**:

1. **Primary Elements — ×5**
2. **Secondary Elements — ×10**
3. **Tertiary Elements — ×15**

This extension is intended to preserve the user's layer-by-layer order. It does not replace, renumber, or retroactively reinterpret the current Earth-report sequence, nor does it mark any Earth report or validation gate complete.

## 2. Scope and sequencing gate

The extension is a **post-Earth research track**. Do not start it merely because one Earth-layer report is finished.

Before the Primary Elements stage begins, record a readiness check that confirms:
- the agreed Earth-layer inventory is explicit;
- each required layer has its required report stages and Master Report, where specified;
- the Research Index links to the authoritative artifacts;
- stable IDs, claim ledgers, references, unresolved questions, and change histories are retained;
- report statuses and verification gates reflect actual work;
- no unresolved discrepancy is silently treated as settled; and
- the owner has reviewed the consolidated Earth-track state.

If any prerequisite is missing, record the blocker and keep this extension **Proposed / Not Started**. This is a documentation gate, not a claim that the prerequisites have already passed.

## 3. The three proposed stages

| Stage | Label | Target notation | Intended research role |
|---|---|---:|---|
| 1 | Primary Elements | ×5 | Establish and define the primary set; document each element's scope, terminology, source basis, evidence class, and limits. |
| 2 | Secondary Elements | ×10 | Investigate proposed relationships, dependencies, interactions, contrasts, and counterexamples involving the primary set. |
| 3 | Tertiary Elements | ×15 | Synthesize system-level relationships and emergent-pattern hypotheses while preserving provenance, disagreements, and uncertainty. |

The stage names and target notations are recorded as submitted. **The operational meaning of ×5, ×10, and ×15 remains to be specified by the owner.** Do not silently interpret them as workload multipliers, numbers of passes, report counts, or independent verification cycles. Define that meaning before scheduling or executing a stage, and record planned versus actual work separately.

The order is sequential: **Primary → Secondary → Tertiary**. A later stage does not waive the evidence, safety, ethical, or verification requirements of an earlier stage.

## 4. Element taxonomy: open specification

The exact membership and boundary of the **Primary**, **Secondary**, and **Tertiary Elements** are not yet defined in this extension. Nor is it yet settled whether each stage addresses the same agreed set of Earth layers or defines a distinct set at each level.

Until the owner specifies this:
- do not invent or infer element names;
- do not assume the three labels mean the classical elements;
- do not treat the labels as established scientific categories;
- do not assume that every stage maps one-to-one onto every Earth layer;
- retain competing interpretations as open questions; and
- mark taxonomy-dependent work **Blocked — element definitions required**.

A future revision should specify for each stage: element names, definitions, inclusion/exclusion criteria, relationship to the Earth-track layers, stable IDs, and the evidence or interpretive framework under which each element is being considered.

## 5. Required workflow for each stage

For each stage, use the governing research lifecycle from `Research/README.md`:

**Define → Research → Model → Simulate → Verify → Falsify → Stress Test → Peer Review → Risk Assess → Mitigate → Document → Repeat**

Apply only the steps that are appropriate and record when a step is not applicable or cannot yet be performed. A simulation must not be claimed unless a model is sufficiently specified and the execution is documented.

Each stage record must include:
1. stage ID, version, owner, dates, and status;
2. definitions, scope, exclusions, and research questions;
3. source-selection method and claim-to-source ledger;
4. empirical, mathematical/computational, historical, interpretive, spiritual/theological, and hypothetical claims kept distinct;
5. proposed links, alternatives, counterevidence, assumptions, and uncertainty;
6. model specification and actual execution records, if applicable;
7. falsification criteria, limitations, risks, and ethical analysis;
8. internal-consistency results;
9. independent-challenge status;
10. reproducibility/regression status;
11. unresolved questions and blockers; and
12. change history and links to prior and downstream artifacts.

Repeated passes are not automatically independent reviews. Count only actual, documented executions.
